## Headline conclusion

V7 is not a bad system, but the strongest 730-day number is materially more optimistic than what I would expect in live trading.

Why:

1. The 730-day compounded result is very strong:
   - `n=164`
   - `WR=45.1%`
   - `PF=1.67`
   - `Return=+1482.7%`
   - `MaxDD=38.1%`
   - `22 / 34` positive months

2. The last year is much weaker:
   - `365d: -9.0%`
   - `PF=0.95`
   - `MaxDD=53.5%`

3. The last 180d and 90d improved again:
   - `180d: +18.6%, PF 1.24, DD 27.1%`
   - `90d: +20.8%, PF 1.50, DD 15.0%`

Interpretation:

- There is likely a real trend-following edge here.
- But it is cyclical and unstable across market phases.
- I would not anchor expectations to `8-9% every month`.
- A more realistic expectation is:
  - long flat / noisy stretches,
  - a handful of strong trend months,
  - occasional deep drawdown clusters if risk is left unchanged.

## Most important audit findings

### 1. Live/backtest bear logic mismatch is large

Backtest research path uses `bear_mode="long_only"` on the regime classifier, while live V7 suppresses shorts when `BTC < SMA50`.

That difference is not cosmetic. When I force the backtest closer to the live BTC<SMA50 short suppression idea, the result drops to:

- `n=184`
- `WR=33.2%`
- `PF=1.02`
- `Return=+19.3%`
- `MaxDD=76.8%`
- `18 / 36` positive months

This is the single biggest credibility warning in the whole audit.

### 2. Live entry assumptions are harsher than the backtest assumes

Backtest fills at next-bar open inside the simulator. Live V7 uses post-only limits first, then expiration / cancellation, and only then a market fallback.

That means the live version can miss some of the cleanest breakout/reversal entries, especially in fast moves.

### 3. The strategy has barely any real live evidence yet

Current live logs on `2026-05-03` show the bot starting and cycling, but no actual V7 fills yet.

So at this point the system is still mostly “backtest-proven”, not “live-proven”.

### 4. Risk can be improved without changing the idea

The strongest low-friction improvement from the existing framework was a daily loss stop:

`daily_dd_limit = 3%`

Result:

- `Return=+1513.1%`
- `MaxDD=28.4%`
- still `21 / 32` positive months

This is better than the current audited base on drawdown with almost no damage to return.

The strongest “defensive” configuration was a portfolio heat cap:

`max_heat = 12%`

Result:

- `Return=+1020.0%`
- `MaxDD=23.2%`
- `PF=1.91`

This sacrifices upside, but materially improves survivability.

### 5. Best month-count tweak from built-in controls

`daily_dd_limit = 3%` + `max_daily_trades = 2`

Result:

- `Return=+770.5%`
- `MaxDD=32.8%`
- `22 / 32` positive months overall
- `8 / last 12` positive months

This is the best simple option if the priority is smoother month count rather than max CAGR.

## Complementary strategy result

I prototyped a separate overlay:

### Bear Donchian 1D 50-bar short overlay

Rules:

- active only when `BTC < SMA50`
- short fresh 50-day downside breakouts
- require symbol below `EMA200`
- entry next daily open
- `SL = 2 ATR`
- `TP = 2R`

Combined with V7 in the same portfolio simulator:

- `n=151`
- `WR=46.4%`
- `PF=1.68`
- `Return=+958.7%`
- `MaxDD=30.3%`
- `23 / 35` positive months
- `9 / last 12` positive months

Meaning:

- lower total return than the raw base V7,
- but materially better drawdown,
- one extra positive month overall,
- noticeably better recent month consistency.

Standalone as a small sleeve (`1% risk`, `max_pos=2`):

- `n=25`
- `WR=68.0%`
- `PF=3.31`
- `Return=+22.3%`
- `MaxDD=3.7%`
- `9 / 12` positive months

This makes it a good candidate as a small separate overlay, not as a full replacement for V7.

## My recommendation

If I had to act conservatively:

1. Keep V7, but stop trusting the raw 730d headline as the main expectation.
2. Before scaling live capital, align live and backtest bear logic.
3. Turn on a daily loss stop in the research/live parity layer.
4. If the goal is smoother months, test:
   - `daily_dd_limit = 3%`
   - `max_daily_trades = 2`
5. For the second strategy, continue with the bear Donchian 1D 50 overlay as a separate sleeve, not merged into V7 logic at first.

## External context

The broad research picture supports this conclusion:

- time-series momentum in crypto is more robust than cross-sectional momentum once realistic frictions are included;
- trend-following is a real phenomenon, but returns cluster in specific regimes;
- microstructure / order-book features can help, but they require high-frequency data and execution-aware research, not just OHLCV backtests.

That means your current direction is intellectually sound. The main problem is not that V7 is “nonsense”; it is that the live implementation and the research stack are not yet close enough to treat the headline backtest as a likely live outcome.
